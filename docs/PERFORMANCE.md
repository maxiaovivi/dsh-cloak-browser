# Performance

[中文](./PERFORMANCE.zh-CN.md)

## Result summary

Benchmarked on 2026-08-15 with Node.js 24.19, Linux x64, AMD Ryzen 9 7940HS,
15 GB RAM, CloakBrowser free Chromium 146, and an already cached browser
binary. The target was a local HTTP page containing 302 interactive elements;
snapshots were capped at 100 refs and 12,000 text characters.

| End-to-end tool operation | `humanize=true` P50 | `humanize=false` P50 |
|---|---:|---:|
| First lazy browser open | 635 ms | 651 ms |
| Subsequent browser open | 183 ms | 184 ms |
| Local navigation | 34 ms | 42 ms |
| 100-ref page snapshot | 29 ms | 30 ms |
| 12,000-character extraction | 1.2 ms | 1.3 ms |
| Viewport JPEG screenshot | 51 ms | 52 ms |
| Snapshot → click → snapshot | 6,273 ms | 161 ms |
| Snapshot → type 15 characters | 11,485 ms | 84 ms |

Approximate Linux process-tree RSS increased by 810 MiB with humanization and
782 MiB without it. This includes the benchmark Node process and every
Chromium descendant. A reading 300 ms after close remained 168 MiB and 137 MiB
above the pre-import baseline respectively; that short-window value includes
loaded Node/Playwright modules and allocator retention and is not, by itself,
evidence of a browser-process leak.

## Interpretation

- Browser startup is sub-second once the binary is cached. The first call also
  pays dynamic module initialization; later Chromium processes opened in about
  183 ms on this machine.
- Snapshot, extraction, and screenshot projection are small compared with LLM
  inference and public-network latency. The thin DSH adapter is not the main
  throughput bottleneck.
- Humanization intentionally dominates interactive latency. It made the tested
  click workflow about 39× slower and the typing workflow about 136× slower.
  This is a stealth/realism trade-off rather than framework overhead.
- The main resource cost is Chromium memory. Because this release uses one
  process-backed session per Agent for isolation, concurrent browser Agents
  should be limited according to available RAM and CloakBrowser licensing.
- Use `humanize=false` for trusted internal testing where throughput matters;
  keep it enabled only where human-like timing is part of the authorized task.
- Humanized typing approaches the ordinary action timeout even for short text,
  so typing has a separate 90-second default timeout (`typingTimeoutMs`).

## Methodology and caveats

- The download and extraction of the approximately 200 MB browser archive were
  excluded. The binary was already cached.
- Navigation used a local HTTP server. DNS, proxy, target-site, and public
  network latency were excluded.
- Results are end-to-end plugin tool-body timings. LLM inference and the outer
  DSH approval/policy/log pipeline were excluded.
- Humanized workflows used three samples; observation operations used five.
  These results characterize this host and are not universal guarantees.
- Screenshot bytes are generated by Chromium, but the benchmark attachment
  store is in-memory so persistent storage latency is excluded.

Raw results are stored in [`bench/results`](../bench/results). Re-run with:

```bash
npm run benchmark:json
node bench/benchmark.mjs --json --no-humanize
```

Use `BENCH_SAMPLES=<n>` to increase the default five observation samples.
